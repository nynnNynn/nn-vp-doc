## 1. Core Concepts（核心概念）

### Single Page Application — SPA（单页应用）

**An SPA renders different application views within a single loaded document.**  
SPA 在同一个已加载的文档中切换应用视图，不要求每次切换都重新加载完整 HTML 页面。（p.9–12）

- **Single page does not mean a single view.** — 一个文档可以包含多个逻辑页面，例如首页、个人资料页。
- **Client-side routing determines the current logical page.** — 客户端需要根据 URL 等信息判断当前应显示哪个视图。
- **An SPA can still communicate with a server.** — SPA 仍然需要加载资源、获取数据和同步状态。
- **【补充】An SPA may have multiple URLs.** — “单页”不代表地址栏永远不变。
- **【补充】Client-side navigation does not guarantee zero network requests.** — 不重新加载整个文档，仍可能请求数据或其他资源。

**Initial loading sequence（课件的首次加载流程）**：（p.10–12）

1. 浏览器请求站点，例如 `GET www.vanderbilt.edu`。
2. 服务器返回 HTML 页面。
3. 浏览器请求 `/js/main.js`。
4. 服务器返回 SPA bundle。
5. 客户端运行路由与视图逻辑。

**On initial load or URL change（首次加载或 URL 改变时）**：（p.12）

1. **Determine the requested page** — 判断用户需要哪个逻辑页面。
2. **Load the appropriate view template** — 选择或加载相应模板。
3. **Fetch necessary data** — 获取需要的数据，不代表每次都必须重新请求。
4. **Render the view** — 将视图渲染到页面。

> `onLoad()` 和 `onURLChange()` 是课件中的流程伪代码名称，不是浏览器自动提供的同名路由 API。

### SPA Responsibilities（SPA 的四项职责）

课件强调，无论选择什么框架，都需要处理以下职责。（p.7、15–17）

| Responsibility | 英文考试表述 | 中文要点 |
| --- | --- | --- |
| Routing | Determine which view corresponds to the current route. | URL 与逻辑页面的对应关系 |
| Views | Render templates and data into the DOM. | 模板与数据生成页面内容 |
| Events | Connect events on elements to handler functions. | 事件类型、目标元素、处理函数 |
| Data | Manage client state and its relationship with the server. | 数据获取、缓存、同步、持久化和更新 |

- **【补充】Webpack is a build tool, not an SPA routing framework.** — 构建工具与运行时框架的职责不同。

### Routing & History API（路由与浏览器历史）

**The History API can change the URL without loading a new document.**  
History API 可以更新地址栏和历史记录，而不重新加载文档。（p.13–14，机制补充见下）

课件的 `setRoute(route)` 顺序：

1. 比较 `route !== window.location.pathname`。
2. 如果不同，调用 `window.history.pushState({}, '', route)`。
3. 使用 `switch(route)` 执行对应分支。
4. 示例分支为 `/index.html` 和 `/profile.html`。

**Code behavior（代码行为）**：

- **Same pathname → skip the entire block.** — 路由字符串等于当前 pathname 时，不入栈，也不执行视图分支。
- **Different pathname → push first, then dispatch.** — 先改变 URL / 历史，再执行 `switch`。
- **No matching case → no matching view logic.** — 示例没有 `default`；未知路由仍可能已入栈，但没有相应视图处理。
- **`break` prevents switch fall-through.** — 匹配分支结束后不继续进入下一个分支。
- **`pathname` excludes query and fragment.** — 单独比较 pathname 不能完整判断包含查询参数或 hash 的状态。

**【课件修正】“Handles all URL changes and events” is a routing requirement, not something this snippet fully implements.**  
课件旁注表示路由系统应处理 URL 变化；给出的片段没有展示初次加载、后退/前进或 hash 事件处理。（p.13–14）

**【补充】History API 易考边界**：

- `pushState()` 本身不加载目标页面，也不自动请求该路径。
- `pushState()` 不会自动渲染视图。
- `pushState()` 本身不触发 `popstate`，也不触发 `hashchange`。
- 浏览器后退/前进等历史遍历可触发 `popstate`，应用需据此更新视图。
- 新 URL 必须与当前文档同源。
- **首次加载与后退/前进不能只依赖课件的条件分支。** URL 已经是目标 pathname 时，再调用同样的 `setRoute(pathname)` 会跳过渲染。
- **【补充】Path-based routing requires suitable server handling for direct visits and reloads.** — 直接访问或刷新 `/profile.html` 时会请求服务器，服务器需能返回应用入口或对应资源。

机制核对：[MDN — pushState](https://developer.mozilla.org/en-US/docs/Web/API/History/pushState)、[MDN — popstate](https://developer.mozilla.org/en-US/docs/Web/API/Window/popstate_event)。

### Views & Templates（视图与模板）

**A template produces HTML from data; DOM insertion displays that HTML.**  
模板根据数据生成 HTML，DOM 操作负责把结果插入页面。（p.15）

- 使用 `import ... from ...` 导入模板。
- 可以渲染简单 HTML fragments，也可以使用复杂 Underscore templates。
- 模板导入、模板执行、DOM 插入是三个不同步骤。
- **【补充】Importing an `.ejs` file requires appropriate build support.** — 不能把这种写法理解为所有浏览器原生支持直接执行 EJS 文件。

**【课件修正】Template variable mismatch（模板变量名不一致）**：（p.15）

- 导入名称：`landingTempl`。
- 调用名称：`landingPage(data)`。
- 如果没有其他定义，直接照抄会因 `landingPage` 未定义而报错。
- 按导入名称统一，应写作：`$("#mainDiv").append(landingTempl(data))`。

### Events & Backbone View（事件与 Backbone 视图）

**An event mapping specifies the event, selector, and handler.**  
事件映射需要明确：监听什么事件、哪些元素、调用哪个函数。（p.16）

课件示例：

- `tagName: 'tr'` — View 的根元素为表格行。
- `'click .add-one': 'addOne'` — 点击 `.add-one` 匹配元素时调用 `addOne`。
- `'click .minus-one': 'minusOne'` — 点击 `.minus-one` 匹配元素时调用 `minusOne`。
- `template` — 通过 Underscore 编译模板。
- `render` — 使用模型属性生成 HTML，写入 View 的根元素。
- `addOne` / `minusOne` — 阻止默认行为，再调用模型方法。

**【补充】Backbone uses delegated DOM events within the view.**  
这里的选择器匹配受该 View 元素范围约束，不是无条件监听整个页面。[Backbone 官方文档](https://backbonejs.org/#View-delegateEvents)

**【课件修正】Arrow functions do not acquire the Backbone view as `this`.**  
课件把 `render`、`addOne`、`minusOne` 写成箭头函数，却在其中依赖 `this.$el`、`this.model`。（p.16）

- 箭头函数继承外层 `this`。
- Backbone 不能通过普通绑定把箭头函数的 `this` 改成 View 实例。
- 按示例意图应使用普通方法，例如 `render() { ... }`、`addOne(e) { ... }`。
- **`preventDefault()` does not stop event propagation.** — 阻止默认动作，不等于阻止冒泡。
- 模型的 `addOne()` / `minusOne()` 是示例自定义方法，不能当作 Backbone 所有 Model 都自带的 API。
- 模型改变是否自动触发重渲染，取决于额外事件监听；该片段没有展示。

### Data Management（客户端数据管理）

**SPA data management includes more than fetching data.**  
SPA 数据管理不只是向服务器发送请求。（p.17）

需要考虑：

- **Fetching / caching / syncing with the server** — 获取、缓存、与服务器同步。
- **Preserving data between sessions** — 跨会话持久化。
- **Intelligent view re-rendering on changes** — 数据变化后合理更新视图。
- **Offline application usage** — 离线使用。

**A framework may or may not address each issue.**  
课件明确说这些问题可能由框架处理，也可能没有；不能推断所有 SPA 框架自动具备缓存、持久化或离线能力。

## 2. Comparisons & Distinctions（易混淆概念对比）

| 对比 | A | B | 考试区分点 |
| --- | --- | --- | --- |
| Client source vs. build output | `src/client/main.js`：源码入口 | `public/js/main.js`：构建产物 | 同名不代表同一文件或职责 |
| Routing vs. rendering | 确定当前逻辑页面 | 根据模板和数据更新 DOM | URL 改变不自动完成渲染 |
| Template compilation vs. execution | 模板文本变成可调用函数 | 向模板函数传入数据，生成 HTML | 两阶段不要混淆 |
| `.append(html)` vs. `.html(html)` | 追加到已有内容之后 | 替换元素内部内容 | 重复 append 可能累积内容 |
| Event handling vs. data management | 响应交互、调用函数 | 改变或同步模型状态 | 点击事件本身不保证持久化 |
| `preventDefault()` vs. stopping propagation | 阻止默认行为 | 阻止事件继续传播 | 不是同一操作 |
| SPA framework vs. Webpack | 运行时应用职责 | 构建与模块打包 | Webpack 不替代客户端路由 |

**Path vs. fragment routing（p.13–14，含机制补充）**：

| 维度 | Path-based routing | Fragment-based routing |
| --- | --- | --- |
| 示例 | `/profile.html` | `/#profile` |
| URL 部分 | pathname | `#` 后的 fragment |
| 浏览器属性 | `location.pathname` | `location.hash` |
| 服务器是否收到该部分 | HTTP 请求包含路径 | HTTP 请求不包含 fragment |
| 常见客户端机制 | History API、`popstate` | hash 修改、`hashchange` |
| 直接访问 / 刷新 | 服务器需能处理该路径 | fragment 不改变服务器收到的路径 |
| 是否等于自动渲染 | 否 | 否 |

Fragment 规则核对：[MDN — URI fragment](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment)。

## 3. APIs & Configurations（API 与配置速查）

### Routing（p.12–14）

- `this.setRoute('/profile.html')` — 调用应用自定义路由函数；是否取数或渲染由实现决定，不是浏览器 API。
- `window.location.pathname` — 同步读取当前 URL 的路径字符串，不包含 query 或 fragment。
- `window.history.pushState({}, '', route)` — 参数依次是关联状态对象、保留参数、目标 URL；同步增加历史项并更新 URL，不自动加载文档或渲染，返回 `undefined`。
- `switch (route) { case '/index.html': ...; break; }` — 按路由字符串执行对应分支；`break` 结束该次 switch 分支执行。

**【补充：理解课件路由所需】**

- `window.addEventListener('popstate', handler)` — 注册历史遍历处理函数；注册本身不异步取数，回调在事件发生时运行。
- `window.location.hash` — 读取 fragment，非空时包含开头的 `#`。
- `window.addEventListener('hashchange', handler)` — 监听常规 fragment 变化；`pushState()` 本身不会触发该事件。

### Views & Templates（p.15–16）

- `import landingTempl from './views/landing.ejs'` — 导入模板模块的默认导出；需要相应构建支持，导入本身不等于插入 DOM。
- `landingTempl(data)` — 按课件意图调用模板函数，用 `data` 生成 HTML；通常同步返回字符串，具体导出取决于 loader。
- `$('#mainDiv').append(landingTempl(data))` — 将模板结果追加到目标元素；同步修改 DOM，返回 jQuery 对象；已修正课件变量名不一致。
- `$('#surfboard-template').html()` — 无参数时读取所选元素的内部 HTML，用作模板源。
- `_.template($('#surfboard-template').html())` — 同步编译模板文本，返回可用数据调用的模板函数。
- `this.template(this.model.attributes)` — 将模型属性传入模板，生成当前视图的 HTML。
- `this.$el.html(html)` — 同步替换 View 根元素的内部 HTML，返回 jQuery 对象。
- `return this` — render 方法返回当前 View，便于链式调用；不表示浏览器自动把它挂载到页面。

### Backbone Events（p.16）

> 以下 `this` 按“已改为普通方法”的预期行为解释。

- `Backbone.View.extend({...})` — 创建 View 子类并返回其构造函数，不是直接创建该 View 的实例。
- `tagName: 'tr'` — 指定自动创建的根元素标签名。
- `events: { 'click .add-one': 'addOne' }` — 将事件类型和选择器映射到 View 方法名称。
- `events: { 'click .minus-one': 'minusOne' }` — 点击对应元素后调用 `minusOne`。
- `e.preventDefault()` — 同步取消可取消事件的默认动作，不阻止冒泡，返回 `undefined`。
- `this.model.addOne()` — 调用自定义模型方法；具体状态变化、返回值及是否通信取决于该方法实现。
- `this.model.minusOne()` — 同上，不能仅凭名称断定自动保存到服务器。
- `this.model.attributes` — 读取 Backbone Model 的属性集合，供模板使用。

## 5. Exam Quick Reference（考前速查）

- **Four responsibilities:** Routing / Views / Events / Data。（p.7）
- **Entry:** `src/client/main.js`；**bundle:** `public/js/main.js`。（p.3–5）

## 1. Core Concepts（核心概念）

### Transpiling — Source-to-source compilation（转译）

**Transpiling translates source code from one language or dialect into another.**  
转译把一种语言或方言的源码转换为另一种源码。（p.3–7）

课件示例：

- **CoffeeScript → JavaScript** — 不同语言之间的源码转换。
- **ES2025 → ES5 (2009)** — 同一语言不同版本之间的转换。
- **High-level language → Assembly code** — 课件用来对比传统编译的示意。

**关键边界**：

- **Transpiling does not necessarily produce machine code.** — 转译输出仍可以是 JavaScript 源码。
- **Transpilation can occur between versions of the same language.** — 不要求输入和输出是完全不同的语言。
- **【补充】Transpilation is a kind of compilation.** — 不能把 compile 与 transpile 当成逻辑上完全互斥的类别。
- **Transpilation supports compatibility with target environments.** — 目标浏览器还不支持某些新语法时，可生成其支持的旧语法。（p.8）

### Babel — JavaScript transformation tool（JavaScript 转换工具）

**Babel is a popular transpiler in the Node.js ecosystem.**  
Babel 是 Node.js 工具生态中的常用转译工具。（p.10）

课件列出的转换用途：

- **ES202X → ES5**
- **JavaScript → Minified JavaScript**
- **React JSX → JavaScript**
- **Other languages → JavaScript**

**【课件限定】These are configurable capabilities, not guaranteed default behavior.**

- 需要对应 parser、plugin、preset 或外部工具支持。
- 不能推断“安装 Babel 后，默认就支持所有语言并自动压缩”。
- p.11 出现 CoffeeScript 是架构示意，不代表标准 Babel 配置原生支持任意 CoffeeScript。
- p.14 的配置只展示 env 与 React presets，未展示 minification 配置。
- **Minification and transpilation have different goals.** — 压缩主要减少代码体积；降级转译主要满足目标语法兼容性。

### Babel Architecture（Babel 架构）

**Babel follows a modular compiler architecture.**  
Babel 采用模块化编译器架构。（p.11）

课件图示：

**Source language / syntax → Parser → IR → Generator → Output code**

- **Parser** — 解析输入源码。
- **IR — Intermediate Representation** — 中间表示，使前后端处理解耦。
- **Generator** — 根据处理后的表示生成输出代码。
- 图中不同输入包括 JSX、ES8 / ES7 / ESX、CoffeeScript，输出示例为 ES5。

**【补充】Babel commonly represents code as an AST and applies transformations before generation.**  
实际理解可采用：解析为 AST → 插件转换 AST → 生成代码。课件的 IR 是概括性表达。

### Targets & Browserslist（目标环境）

**The target environment determines which transformations are needed.**  
需要哪些转换取决于目标浏览器及其版本，不是所有项目都固定输出 ES5。（p.12、14）

- **Browserslist describes target browser versions.** — 用查询规则描述支持范围，供 Babel 等工具使用。
- `last 3 versions` — 每种浏览器最近三个版本，不是整个浏览器市场总共三个版本。
- 目标列表随浏览器版本数据更新，并非永久固定的一组版本。
- Browserslist 不执行转译；真正执行代码转换的是 Babel 等工具。
- **【课件修正】正确名称为 `Browserslist`，配置文件为 `.browserslistrc`。** — p.12 的 `Browserlist`、`.browserlistrc` 少了字母 `s`。

配置规则核对：[Browserslist 官方文档](https://github.com/browserslist/browserslist)。

### Syntax Transformation vs. Polyfills（语法转换与运行时补齐）

**【补充：理解浏览器兼容性必须区分】**

- **Syntax transformation rewrites unsupported syntax.** — 例如 class 转构造函数和 prototype。
- **A polyfill provides a missing runtime feature.** — 例如缺少的标准内置对象或方法。
- **Transpiling syntax does not automatically provide every missing API.**
- p.13 中，`class`、`const` 被改写，但 `localStorage.getItem()`、`JSON.parse()` 仍然存在。
- Babel 不会因为转换了类语法，就自动为不存在的 `localStorage` 实现浏览器存储。
- p.14 未展示 polyfill 配置，不能假设所有缺失能力均已补齐。

`@babel/preset-env` 可按目标选择转换，也能在相应配置下配合 polyfill；**不能据此认为默认补齐所有 API**。[Babel — preset-env](https://babeljs.io/docs/babel-preset-env/)

### ES6 Class → ES5-style Code（类转译代码理解）

课件类结构：（p.8）

- `Hello` 构造函数保存 `this.name`。
- `Hello.prototype.hello()` / 实例方法 `hello()` 返回 `'Hello ' + this.name + '!'`。
- `Hello.sayHelloAll()` 是 static 方法，返回 `'Hello everyone!'`。
- `HelloWorld extends Hello`，构造时调用 `super('World')`。
- `echo()` 调用父类实例方法并弹窗。

| ES6 写法 | 课件 ES5 对应 | 意义 |
| --- | --- | --- |
| `class Hello` | `function Hello(name)` | 构造实例 |
| `constructor(name)` | 构造函数函数体 | 初始化实例状态 |
| `hello() {...}` | `Hello.prototype.hello = function ...` | 原型上的实例方法 |
| `static sayHelloAll()` | `Hello.sayHelloAll = function ...` | 构造函数 / 类上的静态方法 |
| `super('World')` | `Hello.call(this, 'World')` | 用当前实例执行父构造函数 |
| `extends Hello` | `HelloWorld.prototype = Object.create(Hello.prototype)` | 建立实例原型继承关系 |
| `super.hello()` | `Hello.prototype.hello.call(this)` | 用当前实例调用父原型方法 |
| `let hw` | 示例改写为 `var hw` | 为旧语法环境生成代码 |

**Execution results（执行结果）**：

- `new HelloWorld()` 后，`hw.name === 'World'`。
- `hw.echo()` 弹出 **`Hello World!`**。
- `alert(Hello.sayHelloAll())` 弹出 **`Hello everyone!`**。
- `hello()` 返回字符串，本身不弹窗。
- `echo()` 的弹窗发生在调用时，未显式返回值，因此返回 `undefined`。
- `hw.sayHelloAll()` 不会因它是 static 方法就自动可用；static 不属于实例原型。

**【课件限定】The ES5 example is illustrative, not a complete semantic equivalence proof.**

- 单独重设 `HelloWorld.prototype` 没有恢复其自有 `constructor` 属性。
- 片段没有展示子构造函数对父构造函数的静态继承。
- 真正的 Babel 输出可能包含额外 helper；p.13 就展示了 `_classCallCheck`。
- 不要把 `let → var` 理解成任何情况下都能机械替换而不考虑块作用域。

### Manual Execution & Webpack Integration（命令行与集成）

**Babel can run independently of Webpack.**  
Babel 可以从命令行处理单个文件，不要求必须经过 Webpack。（p.13）

**Webpack can invoke Babel through `babel-loader`.**  
Webpack 可以通过 loader 把符合规则的源码交给 Babel。（p.14）

**Configuration flow**：

1. Webpack 的 `module.rules` 判断文件是否匹配。
2. `exclude` 排除指定路径。
3. `use: 'babel-loader'` 调用 Babel。
4. Babel 从配置中获得 plugins / presets。
5. presets 决定启用哪些转换。

**【课件修正】The shown regex matches `.js`, not `.jsx`.**  
p.14 文字说处理 `.js` 或 `.jsx`，代码实际为 `test: /\.js$/`。

- `/\.js$/`：匹配以 `.js` 结尾。
- `/\.jsx?$/`：匹配以 `.js` 或 `.jsx` 结尾。
- 配置了 React preset，**不等于 `.jsx` 文件会自动通过 Webpack 的匹配条件**。
- `.js` 文件内部也可能含 JSX；文件扩展名与文件内语法不是同一个概念。

### Cacher Example（缓存类示例）

p.13 构造函数：

- 创建匹配 `max-age` 数字的正则。
- 从 localStorage 读取 `"data-cache"`。
- 有真值字符串时执行 `JSON.parse(cache)`。
- 否则将 `this.fetches` 初始化为 `{}`。

**Important behavior**：

- 构造时读取的是已有缓存，不是发起网络请求。
- 代码没有写回 localStorage，也没有删除缓存。
- 创建正则不等于已经解析 Cache-Control，更不等于自动执行过期策略。
- 没有缓存时 `getItem()` 返回 `null`，条件表达式选择 `{}`。
- 非空但非法的 JSON 会导致 `JSON.parse()` 抛错；片段没有 `try/catch`。
- 字符串 `"null"` 是真值，解析后结果是 `null`，不是 `{}`。
- Babel 改写代码表达形式，不代表把这些运行时操作提前执行。

## 2. Comparisons & Distinctions（易混淆概念对比）

| 工具 / 概念 | 主要职责 | 不能据此推断 |
| --- | --- | --- |
| Babel | 转换源码语法 / 表示 | 自动打包整个依赖图 |
| Webpack | 模块依赖处理与打包，调用 loaders | 默认完成所有 ES / JSX 转换 |
| `babel-loader` | Webpack 与 Babel 的桥接 | 自己决定所有目标浏览器 |
| Browserslist | 描述目标浏览器版本范围 | 自己执行源码转换 |
| Babel plugin | 单项或特定转换能力 | 必然包含完整环境兼容方案 |
| Babel preset | 一组预配置 plugins | `plugins: []` 时完全没有转换 |
| `@babel/preset-env` | 按目标环境选择 JS 转换 | 默认补齐所有 Web API |
| `@babel/preset-react` | JSX 等 React 相关转换 | 自己负责 DOM 渲染或路由 |
| Minification | 减少输出体积 | 自动解决旧浏览器兼容性 |
| Polyfill | 补运行时缺失能力 | 自动改写浏览器无法解析的语法 |

React preset 职责核对：[Babel — preset-react](https://babeljs.io/docs/babel-preset-react)。

| 对比项 | Instance method | Static method |
| --- | --- | --- |
| 课件方法 | `hello()` | `sayHelloAll()` |
| 定义位置的 ES5 示意 | `Hello.prototype.hello` | `Hello.sayHelloAll` |
| 典型调用 | `hw.hello()` | `Hello.sayHelloAll()` |
| 是否直接属于实例 | 经原型查找可用 | 不因 static 定义而成为实例方法 |

## 3. APIs & Configurations（API 与配置速查）

### CLI（p.13）

- `npx babel src/client/cacher.js` — 调用 Babel CLI 转译指定文件；使用可用配置时得到相应转换，默认向标准输出打印结果，不表示覆盖源文件。
- `npx` — 执行包提供的命令；它本身不是负责 class 转换的转译器。

> **【补充】** 该命令依赖可用的 Babel CLI 与相关配置。仅命令名称本身不保证生成 ES5。

### Webpack Configuration（p.14）

- `module: { rules: [...] }` — 配置模块处理规则。
- `test: /\.js$/` — 只匹配 `.js` 后缀；`$` 表示字符串末尾，不匹配 `.jsx`。
- `test: /\.jsx?$/` — **修正版**，同时匹配 `.js` / `.jsx`；`?` 表示 `x` 可出现零次或一次。
- `exclude: /node_modules/` — 将匹配 `node_modules` 路径的模块排除在该条 loader 规则之外；不表示这些依赖完全不参与打包。
- `use: 'babel-loader'` — 让符合条件的模块经过 Babel 处理。

### Babel Configuration（p.14）

- `babel.config.json` — 课件使用的 Babel JSON 配置文件。
- `"plugins": []` — 没有单独列出的 plugins；presets 仍可带入转换插件。
- `"presets": ["@babel/preset-env", "@babel/preset-react"]` — 同时启用环境相关转换和 React / JSX 相关转换。
- `"@babel/preset-env"` — 按目标环境选择适用的 JavaScript 转换。
- `"@babel/preset-react"` — 处理 JSX 等 React 相关语法；不等于运行 React 应用。

### Target Configuration（p.12）

- `.browserslistrc` — 正确的 Browserslist 独立配置文件名；课件少写一个 `s`。
- `last 3 versions` — 选择每种浏览器最近三个版本，供支持 Browserslist 的工具读取。

### Class / Prototype APIs（p.8）

- `new HelloWorld()` — 创建并返回实例，执行子构造函数；示例将 `name` 初始化为 `'World'`。
- `super('World')` — 在派生类构造函数中执行父类初始化；派生类使用 `this` 前需完成 super 调用。
- `Hello.call(this, 'World')` — 用当前 `this` 调用普通父构造函数，同步设置实例的 `name`；函数自身未显式返回值。
- `Object.create(Hello.prototype)` — 创建一个以 `Hello.prototype` 为原型的新对象并返回；不会执行 `Hello` 构造函数。
- `Hello.prototype.hello.call(this)` — 以当前实例为 `this` 调用父类原型方法，返回问候字符串。
- `Hello.sayHelloAll()` — 调用静态方法，返回 `'Hello everyone!'`。
- `hw.echo()` — 示例中弹出 `'Hello World!'`，返回 `undefined`。
- `alert(message)` — 显示消息弹窗；不是异步请求 API。

### Cacher / Storage / JSON（p.13）

- `new RegExp(/max-age=([0-9]+)/)` — 创建正则对象；捕获组匹配一个或多个数字，本行不执行匹配或过期处理。
- `localStorage.getItem('data-cache')` — 同步返回已存字符串，不存在时返回 `null`，不修改存储。
- `JSON.parse(cache)` — 同步把 JSON 文本转换为 JS 值；非法 JSON 抛 `SyntaxError`，返回值不一定是对象。
- `this.fetches = cache ? JSON.parse(cache) : {}` — 同步修改实例属性；按字符串的 truthiness 决定是否解析，而不是验证缓存是否合法。
- `_classCallCheck(this, Cacher)` — Babel 输出中的辅助函数调用，用于检查类式构造调用；不是浏览器原生全局 API。

# Lecture 14 — Saving State

> 本章共 11 页。特别注意：课件对 Cookie 发送范围、Web Storage 作用域、容量和数据库存储上限有简化表述。

## 1. Core Concepts（核心概念）

### Reload & Client State（刷新与客户端状态）

**A page reload can discard JavaScript variables and in-memory application state.**  
刷新可能丢失 JS 变量和仅存于内存的应用状态。（p.3）

- JS 在新页面执行环境中重新运行，变量重新初始化。
- 不要把“重新运行初始化代码”误认为“旧变量自然保留”。
- **Persistent state requires a preservation and restoration mechanism.** — 需要把状态保存在 URL、存储或服务器等位置，再恢复到运行中的应用。
- **【课件限定】“Everything is reloaded” does not mean every resource must be downloaded again.** — 浏览器可能使用缓存；重点是不能依赖旧页面的 JS 内存。

**Other situations with similar state-loss concerns（p.3–4 的延伸）**：

- 导航到其他文档。
- 关闭页面后重新访问。
- 应用重新启动。

### URL State — Path, Query, Fragment（URL 保存状态）

**The path, query string, and fragment can all encode application state.**  
路径、查询字符串和 fragment 都可以携带状态。（p.5）

| URL 形式 | 课件示例 | 可表达的信息 |
| --- | --- | --- |
| Path | `/map/foo/@36.1555625,-86.7991347,15z` | 用户 / 地点 / 经纬度 / 缩放 |
| Query string | `/map?username=foo&lat=36.1555625&long=-86.7991347,15` | 参数名和值 |
| Fragment | `/map#foo` | 客户端识别的状态标记 |

**【补充】Key distinctions**：

- **Path and query are included in requests; fragments are not.**
- URL 状态便于复制、书签、分享与刷新后重建页面。
- URL 中包含数据，不代表应用会自动解析并恢复它。
- 课件 query 示例的 `long=-86.7991347,15` 是一个参数值；其中的 `15` 不会自动成为独立 zoom 参数。
- URL 和浏览历史可暴露状态，不应将其视作秘密存储。
- Fragment 不发送给服务器，仍能被页面脚本读取，不能据此认为它保密。

Fragment 规则核对：[MDN — URI fragment](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment)。

### HTTP Cookies（HTTP Cookie）

**Cookies store small name–value pairs managed by the browser.**  
Cookie 可以保存小量键值状态，客户端和服务器均有相关读写机制。（p.6–7）

课件重点：

- JavaScript 可以通过 `document.cookie` 访问允许脚本访问的 Cookie。
- 读取多个 Cookie 后提取指定值相对麻烦，因此有库支持。
- **Hard to keep confidential** — 不应把普通客户端可读 Cookie 当成保密存储。
- **Limited in size: about 4 KB per cookie** — 课件的 4 KB 应理解为单个 Cookie 的近似容量限制，不是整个站点全部 Cookie 总共只有 4 KB。
- 符合条件的 Cookie 会随请求自动发送。
- 服务器可通过 HTTP 响应设置、更新或使 Cookie 过期。

**【课件修正】“All site cookies are sent every request” is an oversimplification.**（p.7）

准确表述：

**Only eligible cookies are attached to a request.**  
Cookie 发送受 Domain、Path、Secure、SameSite、过期时间及请求凭据策略等约束。

- 不能说任意网站的全部 Cookie 都发给任意服务器。
- 服务器读到的是请求携带的 Cookie，不是任意读取整个浏览器 Cookie 仓库。
- **`HttpOnly` cookies are inaccessible to JavaScript but may still be sent with requests.**
- `Secure` 限定安全传输，不等于 Cookie 值自动加密，也不等于禁止 JS 访问。

核对：[MDN — Using HTTP cookies](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies)。

### `document.cookie` Is an Accessor（Cookie 属性的特殊读写语义）

**Writing `document.cookie` sets one cookie; reading it returns a cookie string.**  
写入通常设置一个 Cookie，读取返回可见 Cookie 的字符串。（p.6）

- 连续设置 `username`、`lat`、`long`、`zoom`，不会因赋值语法就把前面不同名 Cookie 全部覆盖。
- 相同 name、domain、path 标识的 Cookie 可被更新。
- 读取形式通常为 `name=value; name2=value2`，不是 JS 对象。
- 读取结果不包含 HttpOnly Cookie。
- 不指定 `Expires` / `Max-Age` 时通常为 session cookie；**不是 sessionStorage**。
- 课件正则提取的是 `test2`，而设置函数并未创建 `test2`，不能把结果误认为是 username。
- 字符串 `.replace()` 不修改浏览器中的 Cookie。

读写语义核对：[MDN — Document.cookie](https://developer.mozilla.org/en-US/docs/Web/API/Document/cookie)。

### Web Storage — Shared API Model（Web Storage 共用模型）

**`sessionStorage` and `localStorage` expose a key–value Storage API.**  
二者采用相同类型的键值存储接口。（p.8–9）

**【补充：代码理解必需】**

- **Keys and values are strings.** — 数字写入后读回也是字符串。
- **Operations are synchronous.** — `setItem()` / `getItem()` 等不是 Promise API。
- **Data is not automatically sent to the server.** — 与 Cookie 的重要区别。
- 存对象通常需要 JSON 序列化，读取后再反序列化。
- **Origin = scheme + host + port.** — 精确作用域是 origin，不只是 domain。
- 同主机不同协议或端口通常属于不同 origin。
- 存储访问可能被策略禁止；写入可能因配额不足失败。

机制核对：[MDN — Web Storage](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)、[MDN — Storage](https://developer.mozilla.org/en-US/docs/Web/API/Storage)。

### sessionStorage — Page-session Storage（页面会话存储）

**sessionStorage persists across reloads within the same page session.**  
同一个页面会话中，刷新不会清除 sessionStorage。（p.8，精确作用域为补充）

- **Scoped by origin and top-level browsing context.** — 按 origin 与顶层标签页 / 窗口会话隔离。
- 同一标签页中，相同 origin 的页面可访问对应的 sessionStorage。
- 不同独立标签页不共享同一份可持续同步的 sessionStorage。
- **The session normally ends when the tab/window closes.** — 通常关闭标签页 / 窗口后结束。
- 刷新不是 session 结束。
- 跨 origin 页面无法直接读取另一 origin 的存储。
- 数据量通常远大于单个 Cookie。

**【补充例外】A newly opened page may receive an initial copy from its opener.**  
存在 opener 时，新页面可能获得初始副本；之后两份存储独立变化。会话恢复也使“浏览器关闭必然永久清除”不适合作无条件结论。[MDN — sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)

### localStorage — Persistent Web Storage（持久浏览器存储）

**localStorage has no built-in expiration time and persists across browsing sessions.**  
localStorage 没有内建过期时间，通常跨刷新与浏览器会话保留。（p.9）

- **Scoped by origin.** — 同源页面 / 标签页通常访问同一存储区域。
- 与 sessionStorage 的主要区别是生命周期与标签页隔离方式，不是 API 形状。
- 应用可主动删除某个键，用户也可清除站点数据。
- **【课件限定】“Persists until deleted” is not an absolute durability guarantee.** — 隐私模式、浏览器策略、清理等均可影响保留。
- 不能说 localStorage 会在关闭标签页时自动清除。
- localStorage 与 sessionStorage 是不同区域，相同键名可以有不同值。
- localStorage 不会自动把数据发送给服务器，也不会自动同步到另一设备。

### Storage Quotas（存储容量）

课件原文：（p.8–9）

- sessionStorage：**“10+ MB”**。
- localStorage：**“shares that 10 MB with sS”**。

**【课件修正】Do not treat these numbers as a universal shared-pool rule.**

- MDN 将 Web Storage 概括为每 origin 总计约 **10 MiB**，通常 **5 MiB localStorage + 5 MiB sessionStorage**。
- 不能推断任何浏览器都保证 sessionStorage 单独可用 10+ MB。
- 不能把二者理解为可自由借用剩余容量的统一共享池。
- 达到配额时写入可能抛出 `QuotaExceededError`。
- IndexedDB 使用不同的存储管理机制，不等于也固定只有这 10 MiB。

若题目明确问 **“according to the slides”**，识别课件原数字；若问普遍技术事实，不应把课件数字当成无条件保证。

核对：[MDN — Storage quotas and eviction criteria](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)。

### IndexedDB（索引数据库）

课件列出的特性：（p.10）

- **Large-scale key–value store** — 可保存较大量键值和结构化数据。
- **Transactional** — 通过事务组织操作。
- **Structured queries** — 可进行结构化查询 / 检索。
- **Potentially unlimited in size** — 课件强调相较简单存储更大的容量。
- **More complicated API** — API 更复杂。

**【课件限定与补充】**

- **IndexedDB is not a SQL database.** — “structured queries” 不表示支持 SQL。
- 支持 object stores、keys、indexes 等检索机制。
- 常用 API 主要是异步的，与同步 Web Storage 区分。
- “Potentially unlimited” 不表示真实无限；受浏览器配额、磁盘空间与清理策略限制。

核对：[MDN — IndexedDB terminology](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Basic_Terminology)。

### WebSQL（Web SQL 数据库）

课件列出的特性：（p.10）

- **Acts like a SQL database** — 使用 SQL 数据库模型。
- **Generally built upon SQLite** — 通常基于 SQLite。
- **Requires SQL knowledge** — 需要 SQL。
- 课件同样写了 **“Potentially unlimited in size”**，应理解为容量描述简化。
- **Deprecated** — PPT 已明确标注弃用。

**【补充】WebSQL is not a universally supported modern browser database.**  
不能把 WebSQL 与 IndexedDB 一起理解为“当前所有浏览器都支持的推荐方案”。WebSQL 已经历弃用和移除。[Chrome — Deprecating and removing Web SQL](https://developer.chrome.com/blog/deprecating-web-sql)

> PPT 没有展示 IndexedDB / WebSQL 的具体操作 API，不需额外背一套数据库 API。

### State in an SPA（SPA 中的状态）

**Within a running SPA, ordinary JavaScript can hold client state.**  
SPA 在未刷新、未跨文档跳转时，可以用普通 JS 变量 / 对象保存运行态。（p.11）

但仍需要：

- **Preserve state across reloads.** — 刷新后的持久化与恢复。
- **Coordinate state with the server.** — 与服务器协调数据。
- **Distinguish in-memory state from persistent state.** — 内存保留不等于持久保存。
- **Distinguish persistence from synchronization.** — 写入 localStorage 不等于服务器已经得到数据。

## 2. Comparisons & Distinctions（易混淆概念对比）

### State Mechanisms（状态保存方式）

| 机制 | 主要作用域 | 生命周期 | 自动随请求发送 | 数据形式 / 操作 |
| --- | --- | --- | --- | --- |
| JS variables | 当前运行环境 | 通常随文档重建而丢失 | 否 | 任意 JS 运行态 |
| URL path / query | 当前 URL，可复制分享 | 可通过 URL 重建 | path / query 在请求中 | 应用负责编码与解析 |
| URL fragment | 当前 URL 的 fragment | 可通过 URL 重建 | 否 | 客户端解析 |
| Cookies | 按 Domain / Path 等规则 | session 或设定过期时间 | 符合条件时是 | 小量字符串键值 |
| sessionStorage | origin + 标签页会话 | 刷新保留，通常随会话结束清除 | 否 | 同步字符串键值 |
| localStorage | origin | 跨会话，无内建过期 | 否 | 同步字符串键值 |
| IndexedDB | 通常按 origin 隔离 | 持久存储，但受清理 / 配额影响 | 否 | 结构化数据、事务、主要异步 |
| WebSQL | 历史浏览器本地数据库 | 受实现与策略约束 | 否 | SQL，已弃用 |

### sessionStorage vs. localStorage（p.8–9）

| 维度 | sessionStorage | localStorage |
| --- | --- | --- |
| 共同 API | Storage API | Storage API |
| 值类型 | 字符串 | 字符串 |
| 同步 / 异步 | 同步 | 同步 |
| 刷新后 | 保留 | 保留 |
| 常规关闭标签页后 | 页面会话结束时通常清除 | 通常保留 |
| 独立标签页 | 独立存储；存在初始复制例外 | 同源标签页通常共用 |
| 跨 origin | 不共享 | 不共享 |
| 自动 HTTP 传输 | 否 | 否 |
| 内建逐项过期时间 | 无 | 无 |
| 是否与另一者共用相同键空间 | 否 | 否 |

### Cookies vs. Web Storage（p.6–9）

| 维度 | Cookies | Web Storage |
| --- | --- | --- |
| 核心优势 | 请求自动携带，便于服务器关联状态 | 方便客户端保存更多键值数据 |
| 服务器直接接收 | 符合条件时随请求到达 | 应用需主动发送 |
| 客户端读取 | `document.cookie`，不含 HttpOnly | `getItem(key)` |
| 写入语义 | 一次通常设置一个 Cookie | 按键设置值 |
| 大小 | 单 Cookie 约 4 KB | 通常为 MiB 级配额 |
| 作用域概念 | Domain / Path 等规则 | origin；sessionStorage 另加标签页会话 |
| 自动保密 | 否 | 否 |
| 标签页隔离 | 不等同于 sessionStorage | 取决于 local / session |

### IndexedDB vs. WebSQL（p.10）

| 维度 | IndexedDB | WebSQL |
| --- | --- | --- |
| 数据模型 | 结构化键值 / object stores | SQL 数据库 |
| 查询 | key / index 等，无 SQL | SQL |
| 事务 | 是，课件明确强调 | 数据库事务模型 |
| 常见 API 特性 | 主要异步，较复杂 | 需要 SQL，历史 API |
| SQLite | 不能据此认定为 SQLite 接口 | 课件说通常基于 SQLite |
| 容量 | 较大，但受配额约束 | 不能理解为真实无限 |
| 弃用状态 | 课件未标弃用 | 课件明确 Deprecated |

## 3. APIs & Configurations（API 与配置速查）

### Cookies（p.6–7）

- `document.cookie = 'username=heminggs'` — 设置 username Cookie；不等于覆盖所有其他 Cookie；不指定过期时间时通常是 session cookie。
- `document.cookie = 'lat=36.1555625'` — 设置 lat Cookie，值为文本。
- `document.cookie = 'long=-86.7991347'` — 设置 long Cookie。
- `document.cookie = 'zoom=12'` — 设置 zoom Cookie；读取后不会自动成为 Number。
- `document.cookie` — 同步读取当前文档可见的 Cookie 字符串；不是对象，也不包括 HttpOnly Cookie。
- `document.cookie.replace(/(?:(?:^|.*;\s*)test2\s*\=\s*([^;]*).*$)|^.*$/, '$1')` — 从 Cookie 字符串提取 `test2` 的值；未匹配时返回空字符串；同步返回新字符串，不修改 Cookie，未做 URI 解码。

**课件正则的关键符号**：

- `test2` — 要寻找的 Cookie 名，不是任意变量名。
- `([^;]*)` — 捕获直到分号前的值，可以为空。
- `'$1'` — 用第一个捕获组替换整个匹配。
- 找不到与“找到但值为空”都可能得到 `''`，不能仅凭结果区分。

**【补充：理解服务器读写与生命周期所需】**

- `Cookie: username=heminggs; zoom=12` — 请求头，浏览器携带符合条件的 Cookie。
- `Set-Cookie: username=heminggs; Path=/` — 响应头，服务器要求浏览器设置 Cookie；不是直接修改服务器外任意浏览器数据。
- `document.cookie = 'username=; Max-Age=0; Path=/'` — 使匹配 name / domain / path 的 Cookie 过期；路径等范围必须与目标匹配，不能用于删除 HttpOnly Cookie。
- `HttpOnly` — 禁止脚本通过 document.cookie 访问，仍可参与 HTTP 请求。
- `Secure` — 限制安全传输。
- `SameSite` — 影响跨站请求中的 Cookie 发送。
- `Expires` / `Max-Age` — 控制过期时间；不要与 sessionStorage 的页面会话生命周期混为一谈。

### sessionStorage（p.8）

- `sessionStorage.setItem('username', 'heminggs')` — 同步保存键值；已有同名键则更新，返回 `undefined`。
- `sessionStorage.setItem('lat', 36.1555625)` — 同步保存，数字转换为字符串。
- `sessionStorage.setItem('long', -86.7991347)` — 同步保存字符串形式的数值。
- `sessionStorage.setItem('zoom', 13)` — 同步保存 `"13"`，不是直接保存 Number。
- `sessionStorage.removeItem('zoom')` — 同步删除 zoom；不存在时无效果，返回 `undefined`。
- `sessionStorage.length` — 当前存储区域的键值对数量，不是字节数，不是方法。
- `sessionStorage.key(1)` — 返回索引 1 的键名，不是值；从 0 开始，越界返回 `null`；不要依赖固定键顺序。
- `sessionStorage.getItem('username')` — **理解所需补充**：同步读取字符串，不存在返回 `null`。

### localStorage（p.9）

- `localStorage.setItem('username', 'heminggs')` — 同步保存或覆盖同名键，无内建过期时间，返回 `undefined`。
- `localStorage.setItem('lat', 36.1555625)` — 保存字符串形式的纬度。
- `localStorage.setItem('long', -86.7991347)` — 保存字符串形式的经度。
- `localStorage.setItem('zoom', 13)` — 保存字符串 `"13"`。
- `localStorage.removeItem('zoom')` — 删除 zoom，不影响 sessionStorage 中的同名键。
- `localStorage.length` — 读取 localStorage 键值对数量。
- `localStorage.key(1)` — 返回第二个索引位置的键名；顺序不应当作业务保证。
- `localStorage.getItem('username')` — 同步读取值，不存在返回 `null`；Lecture 13 p.13 也使用此方法。

**【补充：对象存储与读取】**

- `JSON.stringify(obj)` — 将可序列化的 JS 值转为 JSON 文本，不修改原对象；某些输入会失败或有特殊结果。
- `localStorage.setItem('state', JSON.stringify(obj))` — 先序列化，再同步写入字符串；写入可能因配额或访问策略失败。
- `JSON.parse(localStorage.getItem('state'))` — 读取并解析 JSON；非法 JSON 抛错，实际代码应区分不存在与格式错误。
- `Number(localStorage.getItem('zoom'))` — 将读回的数值字符串转为 Number；注意不存在时 `Number(null) === 0`，不能把它误认为已存 zoom 为 0。

### Storage Example — Execution Results（p.8–9）

**Assume the storage area is initially empty.**  
假设初始为空，执行课件函数后：

1. 写入 `username`、`lat`、`long`、`zoom`，共有 4 个键。
2. 删除 `zoom`，剩 3 个键。
3. `console.log(storage.length)` 输出 **`3`**。
4. `storage.getItem('zoom')` 返回 **`null`**。
5. `storage.getItem('lat')` 返回 **`"36.1555625"`**。
6. `storage.key(1)` 返回一个键名，**不能仅凭写入顺序保证一定是 `"lat"`**。

如果初始存储已有其他键，`length` 不一定是 3。更新同名键不会额外增加一项。

- `console.log(value)` — 输出到开发者控制台，不改变存储。
- `alert(storage.key(1))` — 弹出键名，既不读取对应值，也不删除该项。
- `setCookies()` / `useSessionStorage()` / `useLocalStorage()` — 课件自定义函数名，声明函数本身不会执行内部写入，调用后才执行。

## 4. True / False Traps（判断题陷阱）

### Reload / SPA / URL

- **True** — `A reload can discard in-memory JavaScript state.` — 内存变量不能当作跨刷新持久化。（p.3）
- **False** — `Reloading always downloads every resource from the network again.` — 可能使用缓存，课件重点是状态重建。（p.3；限定）
- **False** — `SPAs no longer need persistence because they avoid page transitions.` — 用户仍可能刷新或重新访问。（p.11）
- **True** — `Ordinary JavaScript can maintain state within a running SPA.` — 未重载的运行期间可保存内存状态。（p.11）
- **False** — `Saving state locally automatically synchronizes it with the server.` — 持久化与同步是不同任务。（p.11）
- **True** — `Paths, query strings, and fragments can encode state.` — 三者均可携带状态。（p.5）
- **False** — `The server automatically receives the URL fragment.` — fragment 不在 HTTP 请求中。（补充）
- **False** — `State encoded in a URL restores the UI without application logic.` — 应用仍需解析和恢复。（p.5；补充）

### Cookies

- **True** — `Eligible cookies can be sent automatically with HTTP requests.` — 这是 Cookie 与 Web Storage 的关键差别。（p.7；精确表述）
- **False** — `Every cookie is sent with every request regardless of its destination.` — 存在域、路径、安全与跨站等限制。（p.7；修正）
- **False** — `The server can read every cookie stored in the browser.` — 只能读到相应请求携带的数据。（p.7；修正）
- **False** — `All cookies are readable through document.cookie.` — HttpOnly 不可由 JS 读取。（补充）
- **False** — `HttpOnly cookies cannot be sent to the server.` — 禁止脚本访问不等于禁止 HTTP 传输。（补充）
- **False** — `Secure means JavaScript cannot read the cookie.` — Secure 与 HttpOnly 的职责不同。（补充）
- **False** — `Assigning document.cookie replaces all existing cookies.` — 通常设置一个 Cookie。（p.6）
- **False** — `Reading document.cookie returns a JavaScript object.` — 返回 Cookie 字符串。（p.6）
- **False** — `The 4 KB limit means all cookies for a site must total less than 4 KB.` — 课件数字应理解为单个 Cookie 近似限制。（p.6；限定）
- **False** — `A cookie without an expiration time is the same mechanism as sessionStorage.` — session cookie 与页面会话存储不同。（补充）
- **False** — `The regex on slide 6 retrieves the username cookie.` — 正则明确寻找 `test2`。（p.6）

### Web Storage

- **True** — `sessionStorage survives page reloads.` — 同一页面会话刷新保留。（p.8）
- **False** — `sessionStorage is cleared whenever the user refreshes the page.` — refresh 不等于 session end。（p.8）
- **False** — `All same-origin tabs share one live sessionStorage area.` — 还按顶层标签页会话隔离。（p.8；修正）
- **False** — `A newly opened tab must always start with empty sessionStorage.` — 可能从 opener 得到初始副本。（补充）
- **True** — `localStorage normally persists across browser sessions.` — 无内建过期时间。（p.9）
- **False** — `localStorage is guaranteed to retain data forever.` — 用户清理、隐私模式或浏览器策略可影响保留。（p.9；限定）
- **False** — `Web Storage is scoped only by hostname.` — 精确作用域含协议、主机和端口。（p.8–9；修正）
- **False** — `HTTP and HTTPS pages on the same host necessarily share localStorage.` — 协议不同，origin 不同。（补充）
- **False** — `localStorage and sessionStorage automatically send their contents to the server.` — 需应用主动发送。（p.8–9；补充）
- **False** — `setItem stores a number as a number.` — 读回是字符串。（p.8–9）
- **False** — `getItem returns undefined for a missing key.` — 返回 `null`。（补充）
- **False** — `key(1) returns the value associated with the second key.` — 返回键名。（p.8–9）
- **False** — `length reports the number of bytes stored.` — 返回键值对数量。（p.8–9）
- **False** — `Updating an existing key always increases length.` — 更新不会增加键数。（p.8–9）
- **False** — `removeItem throws an error if the key does not exist.` — 不存在时无操作。（p.8–9）
- **False** — `Web Storage operations return Promises.` — 常用 Storage API 是同步的。（补充）
- **False** — `sessionStorage is guaranteed to provide more than 10 MB in every browser.` — 课件容量不是跨浏览器保证。（p.8；修正）
- **False** — `localStorage can always borrow any unused sessionStorage capacity.` — 不应将课件描述理解成可自由借用的共享池。（p.9；修正）

### Browser Databases

- **True** — `IndexedDB is transactional.` — 课件明确特性。（p.10）
- **False** — `IndexedDB uses SQL because it supports structured queries.` — 结构化检索不等于 SQL。（p.10；限定）
- **False** — `IndexedDB has the same synchronous key–value API as localStorage.` — API、数据能力与异步机制不同。（p.10；补充）
- **False** — `Potentially unlimited storage guarantees infinite available capacity.` — 仍受配额和设备空间限制。（p.10；限定）
- **True** — `WebSQL generally used SQLite and required SQL knowledge.` — 对应课件特性。（p.10）
- **False** — `WebSQL is a universally supported modern storage standard.` — 课件已明确标注 Deprecated。（p.10）

## 5. Exam Quick Reference（考前速查）

- **Reload:** JS 内存可能丢失；缓存资源不等于保留运行态。（p.3）
- **URL state:** path / query / fragment；fragment 不发服务器。（p.5）
- **Cookies:** 小量键值；单项约 4 KB；符合规则时自动随请求发送。（p.6–7）
- **Cookie getter / setter:** 读字符串；写一个 Cookie；HttpOnly 不可读。（p.6）
- **Cookie regex:** 寻找 `test2`；结果 `''` 可表示缺失或空值。（p.6）
- **sessionStorage:** origin + tab；刷新保留，通常关闭会话清除。（p.8）
- **localStorage:** origin；同源标签页通常共用；无内建过期。（p.9）
- **Web Storage:** 同步、字符串键值、不自动上传。
- **Storage methods:** `setItem(k,v)` / `getItem(k)` / `removeItem(k)` / `key(i)` / `.length`。
- **Missing key:** `getItem()` → `null`；`key(i)` 返回键名。
- **Example result:** 初始为空，写 4 删 1 → length 3；已有其他键则不一定。（p.8–9）
- **Quota:** PPT 写 10+ MB / 共享 10 MB；准确性补充为常见 5 MiB local + 5 MiB session，不是任意共享池。（p.8–9）
- **IndexedDB:** 结构化键值、事务、主要异步、非 SQL、有配额。（p.10）
- **WebSQL:** SQL / SQLite / Deprecated。（p.10）
- **SPA state:** 内存状态 + 跨刷新持久化 + 服务器协调，三项都需考虑。（p.11）
